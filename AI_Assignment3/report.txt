==============================================================
  FEATURES
==============================================================

I used all 27 attributes as features (excluding the target for each task).

--- WHY these features ---
Student academic outcomes (G3), mother's job (Mjob), and educational
support (edusupport) are influenced by a wide range of demographic,
social, and behavioral factors. I kept all 27 attributes because:

- Academic history (failures, studytime, absences): directly predict G3
  and reflect how engaged a student is with school.
- Parental factors (Medu, Fedu, Mjob, Fjob, Pstatus): parental education
  and occupation are strong proxies for the home learning environment and
  socioeconomic status, which correlates with grades and support access.
- Lifestyle (Dalc, Walc, goout, freetime, romantic): alcohol use and
  social habits are known risk factors for academic performance.
- School factors (school, reason, internet, higher, nursery): access to
  resources and educational aspirations affect grades and support types.
- Demographic (age, sex, address, famsize, famrel, health, traveltime):
  provide context about a student's personal circumstances.

Dropping any of these would risk losing signal. With only 585 training
samples, the regularization in each model (L1/L2, max_depth, etc.) acts
as the feature selector - it automatically down-weights irrelevant ones.

--- HOW features were encoded ---
Binary columns (school, sex, address, famsize, Pstatus, nursery, higher,
internet, romantic) were mapped to 0/1. For example: sex -> F=0, M=1.
These only have two values so a simple integer mapping works fine and
doesn't add unnecessary extra columns.

Nominal columns with more than 2 categories (Mjob, Fjob, reason, guardian)
were one-hot encoded. I didn't want to number them arbitrarily because
there's no ordering between values like "teacher" and "health" - that would
mislead the model.

edusupport (attribute 16) is special because a student can receive multiple
types of support at the same time. For example "school family" means both
school and family support simultaneously. When used as an input feature
(Tasks 1 and 2), I split it into 3 binary columns - edu_school, edu_family,
edu_paid - so the model can see each type of support independently. For
Task 3, those same 3 columns become the label matrix to predict.

All features were standardized with StandardScaler before training. This
matters especially for SVM and Logistic Regression which are sensitive to
feature scale. For example, absences ranges 0-93 while most other features
are 0-5, so without scaling those models would be dominated by absences.

--- Engineered interaction features ---
Four new columns were created by multiplying pairs of related features:
  - Dalc x Walc:          combined weekly alcohol load (risk signal)
  - failures x studytime: academic risk - a student who fails despite
                          studying suggests deeper learning difficulties
  - Medu x Fedu:          joint parental education level (home environment)
  - absences x failures:  disengagement signal - both skipping class and
                          failing courses indicate low participation

These products capture non-linear joint effects that the raw features
cannot express individually. For example, Dalc=3 and Walc=4 have a
combined effect on grades that is stronger than either alone.

--- Task-specific feature notes ---
Task 1 (predict G3): uses all encoded features except G3. edusupport is
  split into 3 binary input columns.
Task 2 (predict Mjob): uses attributes 1-8, 10-28 (Mjob excluded as
  target). edusupport treated as 3 binary input columns.
Task 3 (predict edusupport): uses attributes 1-15, 17-28. edusupport
  columns become the 3-dimensional binary label matrix.

Model 1: Random Forest Classifier (with SMOTE)
I wrapped Random Forest inside an imbalanced-learn pipeline that applies
SMOTE (Synthetic Minority Oversampling TEchnique) within each CV fold.
SMOTE generates new synthetic examples for underrepresented classes by
interpolating between existing neighbors, rather than just duplicating
them. This means the RFC sees a more balanced training distribution
without being penalized for "easy" majority-class predictions. The SMOTE
step is applied only inside each training fold, so no leakage occurs.

I used k_neighbors=2 (default is 5) because the 'health' class has very
few real samples - a standard 5-neighbor SMOTE would fail to find enough
neighbors. class_weight='balanced' was removed since SMOTE itself handles
class rebalancing.

==============================================================
  TASK 3 - MULTI-LABEL CLASSIFICATION (Predict edusupport)
==============================================================

This is a multi-label task, not multi-class. A student can have multiple
types of support at the same time - for example "school family" means both
school and family support. I treated each of the three types as its own
binary label:
  "no"            -> [0, 0, 0]
  "school"        -> [1, 0, 0]
  "family"        -> [0, 1, 0]
  "paid"          -> [0, 0, 1]
  "school family" -> [1, 1, 0]
  "family paid"   -> [0, 1, 1]

If I had used a regular multi-class classifier here, it couldn't predict
combinations like "school family" at all - that's why the assignment says
this is a multi-label tagging problem.

I used OneVsRestClassifier which trains one binary classifier per label.
Each of the 3 classifiers answers: does this student have THIS type of
support? Their outputs are combined to get the final label vector.

Metrics: subset Accuracy (exact match on all 3 labels) and Hamming Loss
(fraction of individual label predictions that are wrong - lower is better).

Model 1: OneVsRest Logistic Regression
Logistic Regression is a simple linear model but it regularizes well.
I tuned the C parameter which controls how strong the regularization is.

I also searched over the ElasticNet mixing parameter (l1_ratio) which
blends L1 and L2 regularization. l1_ratio=1.0 gives pure L1 (Lasso)
which encourages sparse solutions - useful when many features might be
irrelevant to predicting each support type.

L1 regularization with C=0.1 gave the best test Hamming loss (0.2188)
