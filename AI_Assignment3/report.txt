==============================================================
  FEATURES
==============================================================

I used all 27 attributes as features (excluding the target for each task).
Here is how I encoded them:

Binary columns (school, sex, address, famsize, Pstatus, nursery, higher,
internet, romantic) were mapped to 0/1. For example: sex -> F=0, M=1.
These only have two values so a simple integer mapping works fine and
doesn't add unnecessary extra columns.

Nominal columns with more than 2 categories (Mjob, Fjob, reason, guardian)
were one-hot encoded. I didn't want to number them arbitrarily because
there's no ordering between values like "teacher" and "health" - that would
mislead the model.

edusupport (attribute 16) is special because a student can receive multiple
types of support at the same time. For example "school family" means they
get both school-based and family support. When I used it as an input feature
(Tasks 1 and 2), I split it into 3 binary columns - edu_school, edu_family,
edu_paid - so the model can see each type separately. For task 3, those same
3 columns become the label matrix.

All features were standardized with StandardScaler before training. This
matters especially for SVM and Logistic Regression which are sensitive to
feature scale. For example, absences ranges 0-93 while most other features
are 0-5, so without scaling those models would be dominated by absences.

==============================================================
  TASK 3 - MULTI-LABEL CLASSIFICATION (Predict edusupport)
==============================================================

This is a multi-label task, not multi-class. A student can have multiple
types of support at the same time - for example "school family" means both
school and family support. I treated each of the three types as its own
binary label:
  "no"            -> [0, 0, 0]
  "school"        -> [1, 0, 0]
  "family"        -> [0, 1, 0]
  "paid"          -> [0, 0, 1]
  "school family" -> [1, 1, 0]
  "family paid"   -> [0, 1, 1]

If I had used a regular multi-class classifier here, it couldn't predict
combinations like "school family" at all - that's why the assignment says
this is a multi-label tagging problem.

I used OneVsRestClassifier which trains one binary classifier per label.
Each of the 3 classifiers answers: does this student have THIS type of
support? Their outputs are combined to get the final label vector.

Metrics: subset Accuracy (exact match on all 3 labels) and Hamming Loss
(fraction of individual label predictions that are wrong - lower is better).

Model 1: OneVsRest Logistic Regression
Logistic Regression is a simple linear model but it regularizes well.
I tuned the C parameter which controls how strong the regularization is.

Parameters I tried (10-fold CV, scoring=neg hamming loss):
  estimator__C: [0.01, 0.1, 1, 10, 100]

Best params: C=0.01
Best CV Hamming loss: 0.1794
Test Accuracy: 0.3594, Hamming loss: 0.2188
Training time: 0.16 s

Strong regularization (small C) worked best - the model keeps it simple
which generalizes better for this label structure.

Model 2: OneVsRest Gradient Boosting Classifier
GBC can capture non-linear patterns better than logistic regression. I
wanted to see if a more powerful model would improve things.

Parameters I tried (10-fold CV):

  estimator__max_depth:     [3, 4, 5]

Best params: learning_rate=0.05, max_depth=5, n_estimators=100

Training time: 28.57 s

Both models ended up with the same test score. Logistic Regression had a
slightly better CV Hamming loss (0.1794 vs 0.1822) and was much faster.
The subset accuracy of 0.36 means the model predicts all 3 labels exactly
right about 36% of the time. The Hamming loss of 0.22 is more lenient -
it counts individual label mistakes, so partial matches count.
