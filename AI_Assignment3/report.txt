----- edusupport – special multi-label binary encoding -----
Column 16 (edusupport) stores the *types* of extra support a student receives.
Crucially, a student can have MULTIPLE simultaneous support types (e.g.
"school family" or "family paid"), making this genuinely multi-label data.

    The column is expanded into 3 independent binary features:

      edu_paid    – 1 if 'paid'   appears, else 0
    A student with "school family" gets edu_school=1, edu_family=1, edu_paid=0.
    This correctly captures overlapping labels better than a single integer code.

  For Task 3 (where edusupport is the TARGET):
    The same three-column binary matrix is used as the label matrix Y,
    enabling genuine multi-label classification.

----- Numerical features (standardised with StandardScaler) -----

monotone transformations.  However, StandardScaler is applied before all models
so that the SVM (Task 2) and Logistic Regression (Task 3) converge efficiently

Note: Attribute G3 (final grade) is included as a feature in Tasks 2 and 3 since

==============================================================
  TASK 3 – MULTI-LABEL CLASSIFICATION / TAGGING (Predict edusupport)
==============================================================

Target: edusupport — a MULTI-LABEL attribute.
  Each student may receive support from any SUBSET of {school, family, paid}.
  Examples from the data:
    "no"           → labels [0, 0, 0]  (no extra support)
    "school"       → labels [1, 0, 0]
    "family"       → labels [0, 1, 0]
    "paid"         → labels [0, 0, 1]
    "school family"→ labels [1, 1, 0]  (BOTH school and family – genuinely multi-label)
    "family paid"  → labels [0, 1, 1]

The multi-label structure is observed directly in the training and test data;
treating this as a standard multi-class problem would be WRONG because it
ignores the co-occurrence of support types.

Strategy: One-vs-the-Rest (OvR).
  Three independent binary classifiers are trained, one per label:
    Classifier 1 – school_support?  (yes/no)
    Classifier 2 – family_support?  (yes/no)
    Classifier 3 – paid_support?    (yes/no)
  Predictions from all three classifiers are combined to form the full
  binary label vector for each student.

Evaluation metrics:
  Accuracy (subset/exact-match): fraction of samples where ALL predicted
    labels exactly match the true label set.
  Hamming Loss: fraction of label-instance pairs that are incorrectly
    classified (i.e. label is 1 but predicted 0, or vice versa).
    Lower Hamming loss is better; it is more lenient than subset accuracy
    because partial matches count.

Tuning method: 10-fold cross-validation via GridSearchCV (scoring: negative
  Hamming loss — minimising Hamming loss equals maximising its negative).

--------------------------------------------------------------
Model 1: OneVsRest Logistic Regression
--------------------------------------------------------------
Why chosen:
  Logistic Regression is a well-regularised linear model. Used inside an
  OvR wrapper it trains three calibrated probability classifiers, one per
  label. It is fast and serves as an interpretable baseline. The key
  hyperparameter C controls L2 regularisation: small C = strong regularisation.

Hyperparameters tried (10-fold CV with neg-Hamming scoring):
  estimator__C        : [0.01, 0.1, 1, 10, 100]    — regularisation
  estimator__max_iter : [2000]                       — ensure convergence
  Total combinations: 5 × 10 folds = 50 fits

CV results:
  Best parameters     : C=0.01, max_iter=2000
  Best 10-fold CV Hamming loss: 0.1794
  Strong regularisation (C=0.01) prevents overfitting to noisy labels.

Performance on testing data:
  Accuracy      : 0.3594   (subset / exact-match)
  Hamming loss  : 0.2188
  Training time : 0.31 s

Model 2: OneVsRest Gradient Boosting Classifier

Why chosen:
  Gradient Boosting builds a strong non-linear classifier that can capture

  indicators, and parental education levels predicting support type). Inside
  OvR, it trains three independent GBCs. Expected to have higher capacity

  Hamming loss  : 0.2188

Comparison:
  Both models achieve the same test Accuracy (0.3594) and Hamming loss (0.2188),
  meaning they predict the same distribution of support labels.  Logistic
  Regression obtains a slightly lower CV Hamming loss (0.1794 vs 0.1822),
  suggesting that the linear model generalises better for this label structure.
  The relatively low subset accuracy reflects the inherent difficulty: the
  "family" label dominates the dataset (majority class per-label), so any model
  that correctly identifies the dominant label achieves moderate Hamming loss
  but still struggles with exact full-vector matches.

  Key insight: The multi-label formulation (OvR) is critical here. A naive
  multi-class approach would be unable to output combinations such as
  "school family" or "family paid" and would incur higher error. OvR gives
  each label independent probability, allowing realistic prediction of any
  subset of support types.
